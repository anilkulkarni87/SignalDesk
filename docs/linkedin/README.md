# SignalDesk LinkedIn Publishing Guide

This six-post series introduces SignalDesk as a synthetic AI engineering and
FDE learning journey. Publish only after the GitHub Pages site is live at:

```text
https://anilkulkarni87.github.io/SignalDesk/
```

If a custom domain is added, replace the URLs in all six drafts before posting.

## Recommended sequence

| Post | Theme | Destination |
|---|---|---|
| 01 | Why the journey starts before the model | Home and journey |
| 02 | Structured LLM evaluation | LLM chapters |
| 03 | Retrieval result that changed the design | Evidence scorecard |
| 04 | Bounded agents and human authority | Agent chapters |
| 05 | Product, observability, and deliberate failure | Operations chapters |
| 06 | From AI engineer to FDE | Capstone |

A practical cadence is two posts per week for three weeks. Leave enough time
between posts to answer substantive questions and incorporate useful feedback
into the site.

## Publishing checklist

- Confirm every linked page is live.
- Use the SignalDesk observability screenshot for Post 05 and as the default
  link-preview image.
- Add descriptive image alt text.
- Preserve the words `synthetic`, `frozen`, and `measured` where used.
- Do not convert a curated evaluation result into a production accuracy claim.
- Do not describe hypothetical investigation capacity as realized savings.
- Answer technical questions with the relevant report or chapter, not a broader
  claim than the evidence supports.
- Record substantive questions as potential article or guided-lab improvements.

## What to measure

Impressions and reactions measure distribution. Stronger signals for whether a
course is worth expanding are:

```text
repository visits
course doctor attempts
Lesson 01 completions
questions about missing lessons
GitHub discussions or issues with concrete feedback
people who complete more than one guided lab
```
