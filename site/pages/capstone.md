# FDE Capstone

The capstone is a ten-minute decision narrative, not a ten-minute happy-path
demo. It connects the fictional customer problem, accepted architecture,
measured evidence, permission boundaries, operational behavior, hypothetical
economics, known limitations, and next validation stage.

## Ten-minute structure

| Time | Focus |
|---|---|
| 0:00-0:45 | Establish the synthetic learning boundary |
| 0:45-1:45 | Explain the customer workflow and unvalidated hypothesis |
| 1:45-2:45 | Show the architecture and authority boundaries |
| 2:45-5:15 | Run one grounded synthetic investigation |
| 5:15-6:30 | Review the exact action payload and human decision |
| 6:30-7:30 | Inspect latency, tools, retrieval, cost, and evaluation |
| 7:30-8:45 | Present successes, failed targets, and failure evidence |
| 8:45-10:00 | Recommend the next reversible validation decision |

## What it proves

The repository can generate a repeatable synthetic substrate, evaluate model
and retrieval behavior, enforce bounded tools and human approval, expose a
usable local workflow, observe individual runs, and test named failures.

## What it does not prove

It does not prove real analyst time savings, production reliability, policy
correctness, autonomous action quality, or business impact. Those remain gates
for discovery, independent evaluation, and a read-only shadow pilot.
